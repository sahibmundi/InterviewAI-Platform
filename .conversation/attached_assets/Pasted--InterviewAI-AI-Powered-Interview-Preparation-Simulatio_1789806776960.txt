# InterviewAI — AI-Powered Interview Preparation & Simulation Platform

## 1. Project Overview

Build a production-quality full-stack web application called **InterviewAI**.

InterviewAI is an AI-powered interview preparation platform designed primarily for students, fresh graduates, and software professionals.

The platform should act as a personalized **AI Interview Coach**.

The core workflow is:

**Resume / Profile + Job Description → Personalized Interview → Candidate Answers → AI Evaluation → Detailed Feedback → Weakness Detection → Personalized Preparation → Progress Tracking**

This should NOT look like a basic AI chatbot or college project.

The application should feel like a modern SaaS product that could be demonstrated to recruiters and technical interviewers.

---

# 2. Primary Goals

The application should allow a user to:

1. Create an account.
2. Build a professional candidate profile.
3. Upload a resume.
4. Analyze the resume using AI.
5. Paste or upload a job description.
6. Analyze the job description using AI.
7. Generate a personalized interview.
8. Select interview type and difficulty.
9. Conduct a realistic AI interview.
10. Answer questions through text initially and voice as an advanced feature.
11. Receive AI-based evaluation for every answer.
12. Receive follow-up questions based on previous answers.
13. Complete technical, HR, behavioral, project, and coding interviews.
14. Track performance over multiple interviews.
15. Identify weak topics.
16. Receive personalized preparation recommendations.
17. Generate a final interview report.
18. Retake interviews and compare progress.

# 3. Technology Stack

Use a modern, maintainable architecture.

### Frontend

* React
* TypeScript
* Tailwind CSS
* Modern component architecture
* Responsive design
* Accessible UI
* Lucide icons or another clean icon library

### Backend

Use Python with:

* FastAPI
* Pydantic
* SQLAlchemy

### Database

Use PostgreSQL.

The database architecture should be relational and normalized.

### AI

Integrate an LLM through an environment-variable-based API configuration.

DO NOT hardcode API keys.

Use:

```text
AI_API_KEY
AI_MODEL
DATABASE_URL
```

or appropriate equivalent environment variables.

Create a dedicated AI service layer so the LLM provider can be changed later without rewriting the application.

### Authentication

Implement secure authentication with:

* Registration
* Login
* Logout
* Password hashing
* Secure sessions or JWT
* Protected routes

Never store plaintext passwords.

# 11. AI Interview Engine

This is the core of the application.

The AI interviewer should:

1. Ask one question at a time.
2. Wait for the candidate's response.
3. Evaluate the response.
4. Decide whether a follow-up question is useful.
5. Adjust difficulty when appropriate.
6. Continue until the configured interview length is reached.
7. Generate a final evaluation.

Do not reveal internal AI reasoning or hidden chain-of-thought.

The UI should only display concise explanations, scores, feedback, and recommendations.

---

# 12. Adaptive Interviewing

Implement adaptive questioning.

The interview should not simply be a fixed list of questions.

For example:

```text
Strong answer
      ↓
Increase difficulty
      ↓
Deeper technical question
```

or:

```text
Weak answer
      ↓
Ask a conceptual follow-up
      ↓
Check understanding
```

The AI should consider:

* Previous answer
* Previous score
* Candidate skill level
* Job requirements
* Interview difficulty
* Previous topics

# 15. Answer Evaluation Engine

Every answer should be evaluated using structured criteria.

Evaluate:

* Technical accuracy
* Relevance
* Completeness
* Clarity
* Communication
* Confidence indicators where technically measurable from available input

Use a 0–10 score for individual categories.

Example:

```text
Technical Accuracy      8/10
Relevance               9/10
Completeness            7/10
Communication           8/10

Overall                 8.0/10
```

Then provide:

### What You Did Well

Short bullet points.

### What Could Be Improved

Short bullet points.

### Missing Concepts

Relevant concepts the candidate did not mention.

### Suggested Better Answer

Provide a concise model answer.

Avoid giving unnecessarily long explanations.

# 16. Follow-Up Questions

The AI should be able to ask contextual follow-up questions.

Example:

Question:

> What is a REST API?

Candidate:

> REST API allows communication between client and server.

Follow-up:

> You mentioned client-server communication. Which HTTP methods would you commonly use when working with REST APIs?

Follow-up questions should be relevant to the candidate's previous answer.
